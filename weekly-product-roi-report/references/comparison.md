# 两周环比候选模式

仅在用户明确要求时使用。`compare_weeks.py` 复用现有解析器，每周单独校验后比较相邻的周一至周日，不读旧分析 JSON，不跳过来源校验。运行目录必须全新，源表和简易版入口不变。

```text
python <SKILL_DIR>/scripts/weekly_roi.py preflight
python <SKILL_DIR>/scripts/compare_weeks.py --input-dir <含两周日报的目录> --week-start <本周周一YYYY-MM-DD> --output-dir <NEW_RUN_DIR>
```

前一周由指定周一减 7 天确定。两周都须七天完整；每周每个已出现产品须七条明确日记录，不能把缺日填零。跨周按店铺 + SKU 组合匹配；同 SKU 改名或 SKU 组合冲突停止。仅出现于一周的产品显示缺记录，既不宣称新品/停售，也不把另一周数值补零。整体汇总按各周真实产品范围；范围变化时页面说明，`matched_totals` 另保留共同产品口径。

周投产是各周销售总额÷各周费用总额，投产变化列为本周减上周的倍数差，投产/费用/销售环比为本周值÷上周值−1。上周为零时百分比不可计算，不能返回无限大或捏造 0%；零费用导致投产不可用时，投产环比也不可用。计算使用未四舍五入的周比值，展示舍入不进入计算。

四种经营状态由费用和销售是否大于零定义：有费用有销售、有费用无销售、无费用有销售、无费用无销售。周状态按周合计，日状态按产品日。它们不是盈利判断或广告归因。页面同时显示周状态变化、每日有费无销天数与涉及费用，可一键筛选有这些日期的产品；不加入未经确认的“低费用高比值”阈值。筛选改变产品列表，选择“全部产品”时总量始终为完整周；若单品在新筛选中仍存在，保留选中单品。

候选版输出两周对齐的三图、单品周对照表、两周每日热力表、`analysis.json`。复核时重点看周状态与日状态是否混淆、零基数/缺记录是否明确、匹配身份与来源是否稳定。使用：

```text
node <SKILL_DIR>/scripts/browser_comparison.cjs --html <HTML> --analysis <JSON> --screenshots <DIR> --playwright-module <MODULE_PATH> --browser-channel msedge
```

验证浏览器离线运行、所有单品值、所有筛选、表行点击、两周日期提示、桌面与 360px 布局。截图必须实际查看。新候选用完整原始数据独立复现并与简易版回归同时验证；失败先定位原因，再修正重跑。实际业务报表和测试输入留在本地，不推送到公开仓库。
