# 支持的完成版日报布局

Profile `completed_daily_roi_v1`，当前只支持 `.xlsx`。未识别的 Excel/CSV、无缓存的新建 Excel 或修改口径须先核查与扩展解析器。

动态扫描所有工作表，唯一识别同一行的 `付费总费用`、`综合投产比` 和包含 `真实销售额` 的列。在主表表头区域识别唯一的 `产品（...）`、`店铺`。表内日期位于产品标题所在行、费用列，支持 Excel 日期/日期序号；必须与文件名中唯一 `YYYYMMDD` 一致。

产品明细到 `合计`/`总计` 为止。空店铺只允许从同列的纵向合并单元格读取，不凭上一行猜测。合计后的费用/销售/投产单元格不能还有数据。

接受并独立核算的相关公式：

- 费用：数值，或数值常量的 `+`/`-` 算术（允许括号、负号）。不执行函数或任意代码。
- 主表真实销售：`='工作表'!A1` 形式的单个跨表引用（列/行动态解析、引号转义支持）。来源同一行第一列必须等于产品名。
- 销售来源 SKU：该产品行之前包含 `sku` 的表头所对应列；非空 SKU 组成产品身份。可改变行顺序和工作表名；不假定固定产品数量。数值 SKU 必须是精确范围内的整数，长 SKU 应为文本。
- 销售来源真实销售：`=ROUND(销售总额单元格-刷单单元格,2)`。刷单单元格支持数字/空白，不支持未独立验证的刷单公式。
- 销售总额：`=ROUND(数字常量加减式,2)`。
- 日 ROI 和合计 ROI：`=IF(费用单元格=0,0,销售单元格/费用单元格)`。
- 费用和销售合计：`=SUM(该列明细首行:明细末行)`。

相关数值缓存必须存在，并与独立计算一致。金额采用 Decimal 的分精度 `ROUND_HALF_UP`；主表金额逐日、逐产品汇总为整数分。当前 profile 不支持负费用/负销售，遇到退款等新口径要明确处理规则，不能自动夹成零。

同一输入目录只扫描第一层、排除 `~$` 临时文件。文件名须有一个有效日期。同一目标日必须恰好一份文件；周外文件在审计中列出但不计入。全部产品须在七天都具有明确记录，缺记录不是零。

`analysis.json` 保存来源文件名、SHA-256、金额、相关单元格、真实销售来源、刷单空白状态和审计范围。它属于私有运行数据；报表内不附硬编码机器路径。HTML 只嵌入绘图需要的日期/金额/显示名称，不嵌入源文件路径、SKU 或审计明细（同名身份歧义时在显示名称中加入店铺与 SKU 以区分）。
